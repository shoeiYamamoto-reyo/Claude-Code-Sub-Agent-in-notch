# 要件定義書

- ステータス: **ドラフト v0.1**（ヒアリング回答待ちの項目は「仮」と表記）
- 最終更新: 2026-10-25
- 参考実装: [coucou](https://github.com/louis-cfm/coucou)（MIT）

## 1. 目的
Claude Code を並行で使うとき、各セッションとサブエージェントが「今何をしているか」「自分の判断待ちになっていないか」を、ターミナルを行き来せずに把握・操作できるようにする。Mac のノッチ（ノッチが無い画面では画面上部中央）に常駐する小さな UI で実現する。

## 2. 対象ユーザー（仮）
- 第一の利用者は開発者本人。Claude Code を CLI で複数セッション同時に使う。
- 将来的に OSS として公開できる品質（インストール手順、設定の安全性、ドキュメント）を目指す。

## 3. スコープ
### やること
- Claude Code（CLI）のセッションとサブエージェントの監視
- 権限リクエストの承認／拒否、`AskUserQuestion` への回答
- サブエージェント定義（`~/.claude/agents/`, `<project>/.claude/agents/`）の一覧・作成・編集

### やらないこと（初期）
- Claude Code 以外のエージェント（Cursor, Codex, Gemini CLI など）の対応
- iPhone / Windows / Linux 版、クラウド中継
- チャット機能、外部サービス連携（Stripe, GitHub 等の pill）、音声操作
- coucou のキャラクター（Mochi）やサウンドなどのアセット流用
- ノッチからのエージェントの新規起動（仮。M4 以降で再検討）

## 4. 機能要件
優先度: **Must** = MVP に必須 / **Should** = 早期に欲しい / **Could** = 余裕があれば

### F1. セッション監視
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F1-1 | 実行中の Claude Code セッションをノッチに一覧表示する（プロジェクト名、作業ディレクトリ、状態: 実行中／入力待ち／承認待ち／完了） | Must |
| F1-2 | 各セッションの直近のツール実行（Read / Edit / Bash など）を時系列で表示する | Must |
| F1-3 | セッション内で動いているサブエージェントを親セッションの下にツリー表示し、開始・終了を反映する | Must |
| F1-4 | セッションが承認待ち・入力待ちになったらノッチを展開して知らせる（通知音は任意設定） | Must |
| F1-5 | 一定時間イベントの無いセッションを「停止」扱いにして自動的に片付ける | Should |
| F1-6 | ファイル編集の差分（+N −M）と詳細表示 | Could |
| F1-7 | セッションのターミナル（Terminal.app / iTerm2 等）を前面に出す | Could |

### F2. 承認・回答
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F2-1 | 権限リクエストをノッチに表示し、「許可」「拒否」をクリックで返す | Must |
| F2-2 | 承認はユーザーの明示的なクリック（またはショートカット）でのみ行い、自動承認はしない | Must |
| F2-3 | アプリが起動していない・応答しない場合、hook は即座に終了し Claude Code 側の通常の確認に任せる | Must |
| F2-4 | 複数の承認待ちをキューとして順に表示する | Must |
| F2-5 | `AskUserQuestion` の選択肢をノッチに表示して回答できる | Should |
| F2-6 | 「常に許可」（Claude Code の permission ルールへの追加） | Could |

### F3. サブエージェント定義の管理
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F3-1 | ユーザー（`~/.claude/agents/`）とプロジェクト（`.claude/agents/`）の定義を一覧表示する（name, description, tools, model） | Should |
| F3-2 | 定義を新規作成・編集する（frontmatter のフォーム入力 + 本文エディタ） | Should |
| F3-3 | 保存前に差分を表示し、確認後に書き込む。既存ファイルはバックアップする | Must（F3-2 実装時） |
| F3-4 | frontmatter の検証（必須項目、ツール名、名前の重複・優先順位の警告） | Should |
| F3-5 | 監視中のサブエージェントから、その定義ファイルを開く | Could |

### F4. セットアップ・設定
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F4-1 | hooks のインストール: `~/.claude/settings.json` を日付付きでバックアップ → マージ → 差分表示 → 確認後に書き込み | Must |
| F4-2 | hooks のアンインストール（アプリが追加したものだけを外す） | Must |
| F4-3 | ログイン時に自動起動 | Should |
| F4-4 | ノッチの無いディスプレイでは画面上部中央にノッチ風の領域を表示する。表示するディスプレイを選べる | Should |
| F4-5 | 表示言語: 日本語・英語 | Could |

## 5. 非機能要件
| 区分 | 要件 |
| --- | --- |
| 対応環境 | macOS 15 以上、Apple Silicon 優先（Intel はビルドのみ確認） |
| 安全性 | Claude Code を絶対にブロックしない。hook のアプリ接続タイムアウトは短く（目安 1 秒以内）、失敗時は何も出力せず終了 |
| 安全性 | ユーザーの設定ファイル・定義ファイルを黙って上書きしない（バックアップ → 差分 → 確認） |
| 性能 | 非表示時の CPU 使用率 0 % を目標（ポーリングしない、イベント駆動）。メモリ 100 MB 未満を目安 |
| 性能 | hook イベント受信からノッチ表示まで 200 ms 以内 |
| プライバシー | テレメトリなし。通信はローカル（Unix ソケット）のみ。秘密情報が必要な場合は Keychain |
| 保守性 | 外部依存なし。UI 非依存のロジックは Swift Package（`AgentKit`）に置き、Linux でも `swift test` できる |
| ライセンス | coucou のコードを流用する場合は MIT の著作権表示を残す |

## 6. 前提・制約（要確認）
次の Claude Code 仕様は `claude-code-integration` エージェントで一次情報を確認し、`docs/claude-code-spec.md` に記録してから実装する。
- hooks のイベント一覧とペイロード（特に `PermissionRequest`, `PreToolUse`, `Notification`, `SubagentStart` / `SubagentStop`, `SessionStart` / `SessionEnd`, `Stop`）
- 権限の許可／拒否を hook の JSON 出力で返す方法と、hook のタイムアウト既定値
- サブエージェント実行をセッション内で識別する方法（hook ペイロード、またはトランスクリプト `~/.claude/projects/*/*.jsonl`）
- `AskUserQuestion` に hook から回答できるか
- VS Code 拡張など CLI 以外から起動したセッションで同じ hooks が発火するか

## 7. 未決事項（ヒアリング中）
1. 利用者の範囲（自分用か、配布・公開するか）
2. MVP の優先順位（監視 / 承認 / 定義管理）
3. Claude Code の利用形態（CLI か IDE 拡張か）と同時セッション数
4. 外部ディスプレイでの表示要否
5. ノッチからのエージェント起動・停止の要否
6. 開発・動作確認に使う Mac の環境（Xcode, macOS バージョン）

## 8. 受け入れ基準（MVP）
- Claude Code のセッションを 3 つ同時に動かし、それぞれの状態とサブエージェントがノッチに正しく表示される。
- 権限リクエストをノッチから許可・拒否でき、Claude Code 側にその結果が反映される。
- アプリを終了した状態でも Claude Code が待たされず普段どおり動く。
- hooks のインストール／アンインストールで、元の `settings.json` の他の設定が一切失われない（バックアップから復元できる）。
