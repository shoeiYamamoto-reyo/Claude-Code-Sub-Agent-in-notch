# 要件定義書

- ステータス: **v0.5**（クラウドの Claude Code セッションの表示・承認 F8 を追加）
- 最終更新: 2026-10-26
- 参考実装: [coucou](https://github.com/louis-cfm/coucou)（MIT）

## 1. 目的
Claude Code の作業を「プロジェクト単位」で、Mac のノッチに常駐する小さな UI から指示・監視・操作できるようにする。

- プロジェクト（作業フォルダと実行環境）を最初に登録しておき、その中のサブエージェントに仕事を与える。
- 実行中のセッションとサブエージェントが今何をしているか、自分の判断待ちになっていないかを、ターミナルを行き来せずに把握する。
- サブエージェントの定義をアプリから作成・編集する。

## 2. 対象ユーザー
- 当面は開発者本人専用。Claude Code は **CLI のみ**で使う（IDE 拡張は対象外）。
- 良いものになれば OSS として公開する。そのため、最初から「他人の Mac に入れても安全」な作り（設定の安全な書き込み、外部送信なし、アセットの権利がクリア）にしておく。

## 3. 画面のイメージ
- ノッチ付近（ノッチが無い画面では画面上部中央）に、**丸くてもちもちしたオリジナルキャラクター**が常に小さく表示されている。
- キャラクターは状態に応じて表情・動きが変わる（待機中、作業中、承認待ち、完了、エラー）。
- キャラクター（確定、詳細は [design/character.md](design/character.md)）: 白を基調にした横長の楕円が、重みで少し台形に潰れた形。口・ほっぺは描かず、**表情は目の形だけ**で表す（待機: 点の目、作業中: 「— —」、承認待ち: 見開いた目、完了: 「^ ^」、エラー: 「> <」）。待機中は目でマウスカーソルを追い、ときどきまばたきする。
- マウスを乗せるとウィンドウが展開し、プロジェクト一覧、タスクの投入、実行状況、承認などの操作ができる。マウスを離すと少し待って縮む。
- 承認待ちなど急ぎの用件があるときは、マウスを乗せなくても少しだけ展開して知らせる。
- キャラクターは独自に作る（coucou の Mochi やサウンドは別ライセンスのため使わない）。SwiftUI の描画で作り、画像アセットに頼らない方針。

## 4. スコープ
### やること
- プロジェクトと環境の登録
- サブエージェントへのタスク投入（新規セッションの起動）と停止
- セッション・サブエージェントの監視
- 権限リクエストの承認／拒否、`AskUserQuestion` への回答
- サブエージェント定義の一覧・作成・編集
- 常駐キャラクターとホバーで展開する UI
- （拡張）Claude Code 以外の通知（git、メール、GitHub など）をノッチに集める（F7、[検討メモ](external-notifications.md)）
- （拡張）クラウドで動く Claude Code（claude.ai/code、`claude --cloud`、モバイル、ルーティン、プロジェクトのスレッド）もノッチに表示し、承認する（F8、[ADR-0003](adr/0003-cloud-sessions.md)）

### やらないこと（当面）
- Claude Code 以外のエージェント（Cursor, Codex, Gemini CLI など）、IDE 拡張から起動したセッションの対応保証
- iPhone / Windows / Linux 版
- F8 以外のクラウド中継（アプリの機能をインターネット越しに使うこと全般）
- claude.ai の非公開 API の利用（クラウドセッションの状態は hooks 経由でだけ受け取る）
- 汎用チャット、音声操作
- F7 以外の外部サービス連携（Stripe など）
- 通知センターのデータベースやアクセシビリティ API による、他アプリの通知の読み取り（macOS 15 では不可・不安定）
- coucou のキャラクター・サウンドの流用

## 5. 機能要件

### F0. 常駐キャラクターと展開 UI
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F0-1 | ノッチ付近（ノッチ無しの画面では上部中央）にキャラクターを常時表示する。表示するディスプレイを選べる | Must |
| F0-2 | マウスを乗せると展開、離すと一定時間後に縮む。展開していない間はクリックを下のアプリに通す | Must |
| F0-3 | キャラクターの表情・動きで全体の状態（待機／作業中／承認待ち／完了／エラー）を表す | Must |
| F0-4 | 承認待ち・入力待ちがあるときは自動で少し展開して知らせる | Must |
| F0-7 | 待機中、キャラクターの目がマウスカーソルの方向を追う。カーソル位置の取得は低頻度にし、カーソルが動いていない間は更新しない | Should |
| F0-5 | グローバルショートカットで展開・クイック入力を開く | Should |

| F0-8 | おやすみモード: 時間を決めて（1 時間、明日の朝まで）音を止める。表示は止めない。macOS の集中モードとの連動は M5 で検討 | Should |

### F7. 他アプリ・外部サービスの通知（拡張）
方針と選択肢の比較は [external-notifications.md](external-notifications.md)。他アプリの通知を横取りする公開 API は無いため、通知の元から直接ノッチに届ける。

| ID | 要件 | 優先度 |
| --- | --- | --- |
| F7-1 | 汎用の通知受け口 `notch-notify` CLI（source, title, body, level, 開く先）。アプリ不在時は 300 ms 以内に静かに終了し、呼び出し元を待たせない | Should |
| F7-2 | 通知一覧（「通知」タブ）: 既読・一括既読、クリックで URL／アプリを開く、ソースごとのミュート。Claude Code の承認待ちより後ろに並べ、`attention` のときだけ peek | Should |
| F7-3 | `notch-notify run -- <コマンド>` で長いコマンドの終了（成功／失敗）を通知 | Should |
| F7-4 | レシピ集: git hooks、Mail.app ルール（AppleScript）、ショートカット.app、launchd | Should |
| F7-5 | GitHub 連携: Notifications API でレビュー依頼・メンション・CI 失敗などを受け取る（トークンは Keychain、`X-Poll-Interval` に従う） | Could |
| F7-6 | Slack 連携: ユーザーが作った Slack アプリの Socket Mode でメンション・DM を受け取る | Could |
| F7-7 | 登録したアプリの Dock バッジ（未読数）を表示する（非公開 API のため実験的、既定オフ） | Could |

### F8. クラウドの Claude Code セッション（拡張）
方針は [ADR-0003](adr/0003-cloud-sessions.md)。クラウドセッションの状態を読む・承認する公開 API は無いため、クラウド側の hook からユーザー自身のリレーを通して Mac に届ける。

| ID | 要件 | 優先度 |
| --- | --- | --- |
| F8-1 | クラウドのセッション（claude.ai/code、`claude --cloud`、モバイル、ルーティン）を、ローカルと同じ一覧に「クラウド」の印付きで表示する。クリックで claude.ai/code のページを開く | Should |
| F8-2 | クラウドのセッションの権限リクエスト・`AskUserQuestion` にノッチから答える（明示的なクリックのみ。claude.ai の画面で先に答えたらカードを消す） | Should |
| F8-3 | クラウド側の hook は Claude Code を待たせない: リレーに届かない・Mac が未接続のときはすぐ「判断しない」で終わる | Must（F8 を入れるなら） |
| F8-4 | セットアップ: リレーの URL と端末トークン（Keychain）の設定、接続状態の表示、テスト送信。クラウド環境に登録する内容（許可ドメイン・ネットワークシークレット・hooks）の案内と、リポジトリへの hooks 追加（差分 → 確認 → 書き込み） | Should |
| F8-5 | プロジェクトのスレッドを表示する（M7-0 の検証で hooks を動かす手段が見つかった場合）。見つからない場合は「スレッドを自分の Mac で動かす（Remote Control）」と既存の経路で表示できることを案内する | Could |
| F8-6 | ノッチからクラウドのタスクを始める（`claude --cloud`）・追加の指示を送る（`claude -p --cloud <id>`） | Could |

## 6. 非機能要件
| 区分 | 要件 |
| --- | --- |
| 対応環境 | macOS 15 以上、Apple Silicon 優先 |
| 安全性 | Claude Code を絶対にブロックしない。hook のアプリ接続タイムアウトは短く（目安 1 秒以内）、失敗時は何も出力せず終了 |
| 安全性 | ユーザーの設定ファイル・定義ファイルを黙って上書きしない（バックアップ → 差分 → 確認） |
| 安全性 | アプリから起動するタスクでも、権限モードを勝手に緩めない（既定はユーザーの設定どおり） |
| 性能 | 待機中（キャラクター表示のみ）の CPU 使用率は 0 % に近づける（アニメーションは低頻度、ポーリングしない）。メモリ 100 MB 未満を目安 |
| 性能 | hook イベント受信から表示まで 200 ms 以内 |
| プライバシー | テレメトリなし。アプリ自身の通信はローカルのみ（例外はユーザーが明示的に有効にした F7 の外部連携の API 呼び出しと、F8 のユーザー自身のリレーへの接続だけ）。秘密情報は Keychain |
| 保守性 | 外部依存なし。UI 非依存のロジックは Swift Package（`AgentKit`）に置き、Linux でも `swift test` できる |
| ライセンス | coucou のコードを流用する場合は MIT の著作権表示を残す。キャラクター等のアセットは自作 |

## 7. 前提・制約（確認済み）
次の Claude Code 仕様は M0-1 で一次情報を確認し、[`docs/claude-code-spec.md`](claude-code-spec.md) に記録した（各項目の出典と、実機確認が残っている項目 U1〜U4 はそちらを参照）。要点: 承認は `PermissionRequest` の JSON 出力で返せる／`AskUserQuestion` は `PreToolUse` の `updatedInput` で回答できる／サブエージェント内のイベントには `agent_id` が付く／`claude -p` でも hooks が動き、承認が必要な操作はフックが許可しない限り拒否される。
- hooks のイベント一覧とペイロード（`PermissionRequest`, `PreToolUse`, `Notification`, `SubagentStart` / `SubagentStop`, `SessionStart` / `SessionEnd`, `Stop` など）
- 権限の許可／拒否を hook の JSON 出力で返す方法と、hook のタイムアウト既定値
- サブエージェント実行をセッション内で識別する方法（hook ペイロード、またはトランスクリプト `~/.claude/projects/*/*.jsonl`）
- `AskUserQuestion` に hook から回答できるか
- アプリからタスクを起動する方法: `claude -p` + `--output-format stream-json`、特定のサブエージェントを指定する CLI オプション（`--agent` / `--agents` 等）、セッションの再開（`--resume`）、停止方法
- 非対話モード（`-p`）で起動したセッションでも hooks と権限リクエストが発火し、ノッチから承認できるか

## 8. 受け入れ基準（最初に使い始められる状態）
- キャラクターがノッチ付近に常駐し、マウスを乗せると展開する。待機中の CPU 使用率がほぼ 0 %。
- プロジェクトを登録し、サブエージェントを選んで指示を出すとタスクが始まり、進捗と結果がノッチで見られる。停止もできる。
- ターミナルで手動起動したセッションも同じ一覧に出る。
- 権限リクエストをノッチから許可・拒否でき、Claude Code 側に反映される。
- アプリを終了した状態でも Claude Code が待たされず普段どおり動く。
- hooks のインストール／アンインストールで、元の `settings.json` の他の設定が失われない（バックアップから復元できる）。

## 9. 未決事項
1. 同時に動かすセッション数の目安（UI の詰め込み方に影響。仮に 5 程度まで快適に表示）
2. キャラクターの名前
3. タスクの起動方式（バックグラウンド実行のみか、ターミナルで開く方式も用意するか）→ ADR-0002
4. Xcode のバージョン（Xcode 16 以上が必要）
5. F7 で最初に対応する外部サービス（推奨は GitHub。Slack は需要が固まってから）
6. F8 のリレーを置く場所（推奨はユーザー自身の Cloudflare Workers。ADR-0003）と、プロジェクトのスレッドで hooks を動かす手段（M7-0 で検証）
