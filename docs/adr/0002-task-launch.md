# ADR-0002: タスクの起動は claude CLI を子プロセスで実行する

- ステータス: 提案中（`claude-code-integration` による仕様確認待ち）
- 日付: 2026-10-25

## 背景
ユーザーはノッチからプロジェクトのサブエージェントに仕事を与え、状況を確認し、停止したい（REQUIREMENTS F2）。

## 選択肢
1. **`claude -p "<指示>" --output-format stream-json` を作業フォルダで子プロセスとして起動**し、出力を読む
2. Claude Agent SDK を使う（TypeScript / Python ランタイムが必要）
3. Terminal.app / iTerm2 を AppleScript で開き、対話モードの `claude` を起動する

## 決定（暫定）
1 を基本にする。3 は「ターミナルで開いて続きを手で操作する」（F2-7）の補助として後から追加する。

## 理由
- 外部依存なし（Swift から `Process` で起動できる）。ユーザーが普段使っている `claude` と同じ認証・設定がそのまま使える。
- stream-json でツール実行・応答を逐次受け取れるので、hooks と合わせて詳細に監視できる。
- 2 は Node / Python の同梱が必要になり「外部依存なし」の方針に反する。

## 確認すること
- サブエージェントを指定して起動する CLI オプション（`--agent` / `--agents` 等）。無ければ指示文の先頭で「<name> サブエージェントを使って」と指定する。
- `-p` でも hooks（特に権限リクエスト）が発火し、ノッチの承認で続行できるか。できない場合は権限モード・許可ツールを事前に指定する運用にする。
- セッションの再開（`--resume <session-id>`）で追加の指示を送れるか（F2-4）。
- 停止時（SIGINT / SIGTERM）の挙動とトランスクリプトの扱い。

## 影響
- `claude` 実行ファイルの場所を検出・設定する必要がある（F6-3）。
- 子プロセスの出力は常に読み続ける必要があるため、待機中 CPU 0 % の目標はタスク実行中は対象外とする。
